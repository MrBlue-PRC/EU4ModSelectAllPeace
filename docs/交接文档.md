# SelectAll（一键全选省份）交接文档

> 最后更新：2026-10-27 ｜ 插件版本 v1.7 ｜ 适用 eu4.exe 1.37.0 / 1.37.5（Steam 64 位版）
> 本文档面向后续维护者，覆盖架构、逆向结论、构建与发布流程、维护场景。

---

## 1. 项目概览

在和谈界面**一键全选对方全部省份**的快捷工具，分两个部分发布：

| 部分 | 位置 | 分发方式 |
|---|---|---|
| 工坊 Mod | 本仓库 `SelectAllPeace/` | Steam 创意工坊（不含二进制） |
| 插件 DLL | 源码本仓库 `plugin/`，成品 `plugin/release/` | GitHub Release，**依赖 EU4dll 加载器** |

**核心设计原则：快捷操作而非作弊。** 所有选中都走游戏原生"加入条款"管线
（CanAdd 校验 → Add → 刷新），战争分数/外交点/侵略扩张/阶级领土变化与手动
逐个点选**完全一致**。未装插件时 Mod 无副作用（条款可见但零效果）。

## 3. 工作原理（端到端）

```
游戏启动
  └─ version.dll(EU4dll加载器) → LoadLibrary plugins/*.dll → selectall.dll
       ├─ DllMain 内联初始化（不用 CreateThread，规避 loader lock）
       ├─ FindPattern 解析 6 个引擎函数地址（唯一特征码，无硬编码偏移）
       ├─ 条目构造/析构/add/remove 四处 5 字节 E9 hook（近端桩+绝对跳转）
       └─ IAT 钩 user32!PeekMessageW（名字查 OriginalFirstThunk！）
            └─ 每次消息泵：热键 T 边沿检测 + 处理待办标记

和谈界面打开
  └─ 条目UI构造 hook 捕获视图指针 g_view（条目析构置失效标记）

玩家触发（两途径等价）
  ├─ 按 T ──────────────────┐
  └─ 点击条约"吞并全部省份(全选)" → add hook 识别（条款名前缀
     sa_peace_select_all，entry+0x30→def→def+0x10 名字串）
     → 正常加入(显示勾选) + 置待办 ──→ 下一帧消息泵执行全选：
        遍历视图条目向量（索取 view+0x290 / 给予 view+0xd0）
        → EntryType(entry)==3（割让省份条目，虚调用 vt+0x78）
        → 未选中(+0x20) 且 canAdd 通过（第3参必须传零初始化24字节！）
        → add 逐个加入 → refresh(view)

省份被取消选中
  └─ remove hook 发现省份条目(type 3)被移除 → 待办 → 下一帧
     找到已勾选的 sa_peace_select_all 条目 → remove → refresh（自动反选）
```

## 4. 关键逆向结论（eu4.exe 1.37.5，括号内为 1.37.0 旧地址）

| 函数 | 1.37.5 地址 | 作用 / 备注 |
|---|---|---|
| 条目UI构造 | `0x1413124f0`（旧 0x14130ef80） | ctor(entryUI, ctx, **view**, entryObj)；hook 点捕获 view |
| 条目UI析构 | `0x141306750`（旧 0x141303220） | deleting dtor(entryUI, flag)；hook 点置 view 失效 |
| canAdd | `0x14097a1c0`（旧 0x1409789d0） | char canAdd(container, entry, outVec, 0, 0)；**outVec 不可空** |
| add | `0x14097a790`（旧 0x140978fa0） | add(container, entry, 0, 0)；hook 点做条款拦截 |
| remove | `0x14097a8d0`（旧 0x1409790e0） | remove(container, entry, 0, 0)；hook 点做反选联动 |
| refresh | `0x141309120`（旧 0x141305bb0） | refresh(view) |
| 条目点击 | `0x141313e70`（旧 0x1413108c0） | 参考实现（selected 判断+canAdd/add/remove+refresh） |

**对象布局**（逆向自 `peaceoffer.cpp:61` 断言与 `PEACE_` 名字拼接处）：
- 和谈视图：模式字节 `+0x660`（0=索取 1=给予）；索取条目向量 `+0x290`、容器 `+0x208`；给予条目向量 `+0xd0`、容器 `+0x48`
- 条目对象：打包目标ID `+0x10`（高32位）、选中标志 `+0x20`、条约定义指针 `+0x30`（非自定义条款为空）
- 条目类型：虚调用 `vt+0x78(entry, buf)` 返回描述符，首 DWORD = 类型；**3=割让省份**，0x27=自定义条约（页签取 def→category）
- 条约定义：名字字符串 `def+0x10`（Clausewitz 串：SSO buf@+0x10 / len@+0x20 / cap@+0x28，cap>15 时 +0x10 为指针）

特征码（每个在 .text 唯一，见 dllmain.cpp `InstallAll()`；游戏更新后用
`FindPattern` 重新提取函数头 16–40 字节验证唯一性即可适配）。

**踩坑记录**（勿重蹈）：
1. IAT 遍历名字必须查 OriginalFirstThunk——FirstThunk 加载后已是函数地址，误当名字表读=启动崩溃（0xC0000005）
2. E9 rel32 跳 DLL 内 handler 可能超 ±2GB——必须"近端桩+movabs 绝对跳"
3. DllMain 里 CreateThread 有 loader lock 死锁风险——内联初始化
4. `variable_arithmetic_trigger` 在条约 is_visible 里不被支持（静默隐藏整个条款）——用普通触发器
5. 脚本层无法按修正计费（warscore_cost 只有静态倍率；变量不能作效果参数）——所以才有本插件方案
6. canAdd 第 3 参传 nullptr 必崩——传零初始化 24 字节缓冲
7. bat 文件必须 CRLF；MSVC 编译中文注释源码加 `/utf-8`

## 5. 构建与发布流程

### 改插件
1. 改 `plugin/dllmain.cpp`
2. `cmd /c build.bat`（需 VS2022，脚本自带 vcvars64）
3. 拷 dll 到游戏 `plugins/`（游戏开着会占用，关游戏再拷）
4. 打发布包：dll + 安装说明 → zip

### 改文案（本地化，源文件在仓库 `SelectAllPeace/localisation_src/`）
1. 改 `SelectAllPeace/localisation_src/sa_select_all_l_simply_chinese.yml`（中文源）
2. 在 `SelectAllPeace/` 下执行 `python localisation_src/mqga_convert.py encode <源> localisation/sa_select_all_l_simply_chinese.yml`
3. 同内容换 `l_english:` 头再 encode 到 `localisation/sa_select_all_l_english.yml`（中文玩家游戏多为英文语言）
4. `verify` 校验往返一致；产物必须 UTF-8 BOM
5. `python tools/sync_mod.py` 同步到游戏 mod 目录

### 发布
- 工坊：用启动器上传 Documents mod 目录下的 SelectAllPeace。上传弹窗里有缩略图框（点击/拖拽添加），选仓库里的 thumbnail.png。
  注意：EU4 启动器（launcher-v2）的 mod 列表封面只认 Steam/Paradox 平台元数据
  （.launcher-cache/steam-mod-thumbnail-*），本地 mod 一律占位图、不看文件夹里的 thumbnail.png；
  上传成功关联工坊物品后封面才会显示
- DLL：zip 放 GitHub Release/网盘（仓库 `plugin/release/` 亦有），链接写进工坊说明页（工坊禁止二进制）
- 版本号同步四处：dllmain.cpp 版本日志、zip 文件名、descriptor.mod、工坊 description

## 6. 常见维护场景

| 场景 | 操作 |
|---|---|
| 游戏大版本更新 | 症状：日志 `pattern resolve FAILED`。流程：Ghidra 重导入新版 exe（`analyze_peace.bat`）→ 在 `peace_decompiled.c` 里按第 4 节特征重新定位函数与布局 → 更新 dllmain.cpp 特征码与偏移 → 重编译 |
| 改热键 | dllmain.cpp 中 `GetAsyncKeyState('T')` 两处（改 VK 码） |
| 改条款名 | **三处耦合**：条约文件对象名、本地化三键（desc/CB_ALLOWED/PEACE_）、dllmain.cpp `strncmp` 前缀（长度同步改） |
| 加"给予页也支持" | 已支持（模式自动识别）；加其他页签类型改 `EntryType()==3` 过滤 |
| T 也想勾选条约 | Hook_PeekMessageW 的热键分支里，全选前对快捷条目补一次 add |

## 7. 已知限制与合规

- 仅 eu4.exe 1.37.x；与 EU4dll 断行插件等 plugins/ 内其他插件共存
- 联机：只调用原生函数、不改游戏数据，理论无 desync，但进程修改风险自负
- 铁人成就：属第三方进程修改，合规性自负
- 二进制补丁属 EULA 灰色地带：非官方、与 Paradox 无关、按 MIT 开源（插件源码）
- 无插件时：条款可见、零费用、点击只加入空条款（设计好的降级）

## 8. 故障排查

| 症状 | 看什么 |
|---|---|
| 游戏启动崩溃 | Windows 事件查看器→应用程序→错误模块/偏移；用 capstone 反汇编 dll 内偏移定位 |
| 按 T 无反应 | DebugView（`[SelectAll]` 日志）：`pattern resolve FAILED`=特征失效；`view=0`=没捕获到视图（先开一次和谈界面） |
| 条款点击无反应 | 日志有无 `shortcut treaty clicked`；没有=add 路径变化，需重新逆向条约页点击入口 |
| 全选误选条约 | `EntryType` 过滤失效（类型枚举变了），对照新版 `FUN_141303530` 的 switch |

## 9. 历史决策（为什么是现在这个形态）

1. **脚本层做不到正常计费的全选**（见踩坑 5）——半动态分档条约方案因引擎不支持
   变量触发器而失败，最终放弃"脚本计价"，改走"原生管线自动化"
2. **hook UI 点击链路而非模型层直改**——保证一切费用/AE/地产变化与手动一致，
   且联机安全；这也是选 `add/remove` 两个函数而非直接改容器数据的原因
3. **条款命名前缀识别**（`sa_peace_select_all`）——引擎拼 `PEACE_+def->name`
   的数据路径稳定，且天然区分于 vanilla 脚本条约
4. **发布拆两包**——工坊禁二进制的硬约束 + DLL 依赖 EU4dll 加载器

## 9.5 1.37.5 兼容性调研结论（2026-10-26）

1.37.5（2024-10-17 发布，checksum 491d，public 分支 buildid 15918133）是 EU4 最终版本。
对比样本：1.37.0 md5 `e300e71f0c48ca2704d39d5bea1c5d96` / 1.37.5 md5 `5af10c50faebd12408149a3a27deffcb`
（1.37.5 exe 样本经 Steam 控制台 `download_depot 236850 236852 8981783487284195911` 获取，
留存维护者本地）。

**selectall.dll v1.7（2026-10-27）已适配 1.37.5，双版本（1.37.0/1.37.5）可用**：
- 6 个特征码中 5 个原本就唯一命中（和谈 UI 函数整体平移 +0x3530~0x35B0 不等，容器函数 +0x17f0，函数体一致）
- **dtor 特征码重制**：v1.6 把 RIP 位移（A7 FD A6 00）写死导致平移即失配；
  v1.7 改为"三组 lea vtable 位移通配 + 尾部 mov edx,0xE0（deleting dtor 对象大小）判别"的
  84 字节通配特征码，1.37.5 上唯一命中 0x141306750，且理论上同时兼容 1.37.0（旧函数尾部序列相同）
- 布局探针全部存活：refresh 内嵌 0x48/0x208/0x660、点击函数同款序列均唯一命中；IAT PeekMessageW 正常
- InstallAll 为全或无：任一失配即不打任何钩子 → 失配时插件无副作用但功能消失
- 静态验证工具：`tools/scan_patterns.py`（v3：通配感知 + 1.37.5 基线地址 + 布局探针 + IAT）

**双字节补丁（EU4dll，matanki-saito）build 93 在 1.37.5 上无需任何改动**：
- 版本门控把 1.37.x 全系（case 370~375）归入 v1_37_0_0 桶（develop 分支 GetVersionFromExe，2024-10 已加）
- 版本不符/特征失配的行为是弹窗 + `exit(-1)`（游戏无法启动），但已用运行日志
  `pattern_eu4_jps_2.log` 中全部 71 条真实特征码离线比对：**1.37.0 与 1.37.5 命中完全一致，0 失配**
- 其特征码设计值得借鉴：call/rip 位移全部通配，天然跨小版本

**升级检查清单（1.37.0 → 1.37.5，2026-10-26 已完成升级并实测）**：
| 项 | 结论 |
|---|---|
| EU4dll 双字节补丁（version.dll/d3d9.dll/plugin64.dll） | 保留现状，无需重打（已实测生效） |
| selectall.dll | v1.7 已适配（见上），release/selectall_v1.7.zip 已打包 |
| 工坊 Mod + 双字节本地化文件 | 不受影响（脚本层） |
| 1.37.5 专属变化 | 旧 DLC 并入本体（DLC 检测类工具可能受影响，与本项目无关） |
| 回退方案 | Steam beta 分支可无密码回退到任意历史版本（1.27.2~1.37.5 全部在列） |
